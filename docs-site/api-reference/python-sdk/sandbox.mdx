## `Sandbox`

### Create, run, clean up — the basic loop

```python
from sandkiln import Sandbox, SandkilnApiError

sandbox = Sandbox.create(tags={"env": "ci", "owner": "pipeline"}, vcpu_count=2, mem_size_mib=1024)

result = sandbox.run_command("python3", ["analyze.py", "--input", "data.csv"])
if result.exit_code != 0:
    raise RuntimeError(f"analyze.py failed: {result.stderr}")
print(result.stdout)

sandbox.write_file("/tmp/report.json", '{"ok": true}')
report = sandbox.read_file("/tmp/report.json")

# One-shot run, never needed again -- skip the snapshot entirely.
sandbox.stop(keep=False)
```

- **`Sandbox.create(name=None, tags=None, base_url=None, auth_token=None, vcpu_count=None, mem_size_mib=None, image_id=None, rate_limit=None, drives=None)`** — boots a sandbox. `name` is a caller-given identity, unique among live sandboxes and held snapshots (`409` if already taken) — see `by_name`/`get_or_create` below. `vcpu_count`/`mem_size_mib` override the daemon's configured defaults, subject to its ceiling. `image_id` boots from a registered image instead of the default rootfs (see [Image](/api-reference/python-sdk/image)). `rate_limit` caps host I/O via Firecracker's own token-bucket limiter (unlimited if omitted). `drives` is a list of `DriveAttachment` to attach existing persistent drives (see [Drive](/api-reference/python-sdk/drive)). A call with no `drives`/`rate_limit` matching a configured pool's image/resources transparently resumes a warm snapshot instead of cold-booting — see [Pool](/api-reference/python-sdk/pool).
- **`sandbox.run_command(command, args=None, env=None, timeout=None)`** — returns an `ExecResult` (`stdout`, `stderr`, `exit_code`). `env` is merged over the sandbox's own `env`. `timeout` is a limit in whole seconds enforced inside the sandbox (at least 1, at most the daemon's `exec_timeout_secs`, which is also the default): on expiry the command's whole process group is killed and `SandkilnExecTimeoutError` (a `SandkilnApiError` with `status == 504`) is raised, carrying `stdout`, `stderr` and `timeout_secs`. Nothing is left running in the sandbox. `AsyncSandbox.run_command` takes the same arguments.
- **`sandbox.read_file(path)`** — returns file contents as `bytes`.
- **`sandbox.write_file(path, content)`** — `content` is `str` or `bytes`.
- **`sandbox.chmod(path, mode)`**, **`sandbox.chown(path, uid, gid)`**, **`sandbox.mkdir(path, parents=False)`**, **`sandbox.rename(from_path, to_path)`**, **`sandbox.copy(from_path, to_path)`**, **`sandbox.symlink(target, link_path)`**, **`sandbox.readlink(path)`**, **`sandbox.truncate(path, size)`**, **`sandbox.list_dir(path)`** (returns `list[DirEntry]` with real `is_dir`/`is_symlink`/`size`/`mode`/`mtime` metadata) — the full filesystem operation set.
- **`sandbox.stop(keep=None)`** — stops the sandbox. Default (`keep` omitted or `True`) preserves state as a resumable snapshot, returns a `StopResult(kept, snapshot_id)`. `keep=False` fully destroys instead.

### Attaching to an id you already have

```python
import os
from sandkiln import Sandbox

# A worker process that only has an id passed to it -- no create() round-trip needed.
sandbox = Sandbox.attach(os.environ["SANDBOX_ID"], auth_token=os.environ["SANDKILN_TOKEN"])
sandbox.run_command("echo", ["still here"])
```

- **`Sandbox.attach(id, base_url=None, auth_token=None)`** — wraps an existing sandbox id without a network round-trip.

### Named sandboxes — find the same environment again later

```python
from sandkiln import Sandbox, SandkilnApiError

# First call today: creates a fresh sandbox named "agent-session-42".
# Every later call, any day: resumes it if it was stopped, returns it as-is if still live.
sandbox, created = Sandbox.get_or_create(name="agent-session-42")
if created:
    sandbox.run_command("pip", ["install", "-r", "requirements.txt"])  # one-time setup
sandbox.run_command("pytest")
sandbox.stop()  # preserved by default -- nothing to do here

# Elsewhere: resolve the same name to a *live* sandbox without creating anything.
try:
    live = Sandbox.by_name("agent-session-42")
except SandkilnApiError as e:
    pass  # 409 if the name currently belongs to a stopped sandbox -- use get_or_create for that
```

- **`Sandbox.by_name(name, base_url=None, auth_token=None)`** — resolves a name to a *live* sandbox. Raises `SandkilnApiError` (`409`) if the name currently belongs to a stopped (snapshotted) sandbox instead — use `get_or_create` for that.
- **`Sandbox.get_or_create(name, tags=None, base_url=None, auth_token=None, vcpu_count=None, mem_size_mib=None)`** — resolves `name` to a sandbox in one race-safe call: live as-is, resumed if stopped, created fresh otherwise. Returns `(sandbox, created)`.

### Listing and filtering

```python
ci_sandboxes = Sandbox.list(tags={"env": "ci"})
for info in ci_sandboxes:
    print(info.id, info.name, info.created_at)
```

- **`Sandbox.list(tags=None, base_url=None, auth_token=None)`** — lists sandboxes; `tags` filters by exact match on every given key.

### Dev-server preview

```python
sandbox = Sandbox.create()
sandbox.run_command("sh", ["-c", "npm run dev &"])  # background the dev server
url = sandbox.preview_url(3000, path="/health")
print(url)  # open this in a browser, or request it yourself
```

- **`sandbox.preview_url(port, path="/")`** — the URL a browser can open to reach a server listening on `port` inside the sandbox.

### Local tunnel

The reverse of preview: expose a service running on **this machine** to code inside the sandbox. One of the WebSocket-based features (with `pty()` and `attach_logs()`), all on one hand-rolled RFC 6455 client, since the standard library has none.

```python
sandbox = Sandbox.create()
tunnel = sandbox.tunnel(8080, local_port=3000)
# Code inside the sandbox connecting to 127.0.0.1:8080 now reaches
# whatever's listening on this machine's 127.0.0.1:3000.
sandbox.run_command("curl", ["http://127.0.0.1:8080/"])
tunnel.close()
```

- **`sandbox.tunnel(guest_port, local_port, local_host="127.0.0.1")`** — returns a `TunnelHandle` with `.tunnel_id` and `.close()`. The relay runs on a background thread (`AsyncSandbox.tunnel(...)` runs it as an `asyncio.Task` instead). See [Local tunnel](/concepts/local-tunnel).

### Interactive shell (PTY)

`run_command` waits for one command and returns everything at once. `pty()` opens a real interactive shell you can drive:

```python
sandbox = Sandbox.create()
with sandbox.pty(cols=120, rows=40) as pty:
    pty.send("echo $((6 * 7)); stty size\n")
    seen = b""
    while b"40 120" not in seen:
        seen += pty.recv(timeout=10)   # bytes: stdout and stderr interleaved
    pty.send("exit\n")
```

- **`sandbox.pty(cols=80, rows=24)`** — returns a `PtySession`. `send(data)` (`bytes` or `str`) is the shell's stdin; `recv(timeout=None)` returns the next message as `bytes`, or `None` once the shell ended (a `timeout` in seconds raises `TimeoutError` and leaves the session usable); iterating the session yields messages until it ends. It is a context manager, and `close()` ends the shell and anything it started. `cols`/`rows` size the terminal once, at open; the daemon has no live resize. A refused session raises `SandkilnApiError` before any connection is made (`404` unknown sandbox, `409` at the per-sandbox session cap). `AsyncSandbox.pty()` returns an `AsyncPtySession` (`await send()`, `await recv()`, `async for`, `async with`).

The WebSocket client is hand-rolled on the standard library, so there is still no runtime dependency; the auth token goes as the `?token=` query parameter the daemon's WebSocket routes accept.

### Streamed background exec

For a long-running command you want to watch live, start it in the background and attach to its output:

```python
session_id = sandbox.exec_stream("sh", ["-c", "for i in 1 2 3; do echo tick $i; sleep 1; done; exit 5"])

with sandbox.attach_logs(session_id) as logs:
    for message in logs:               # replay, then live tail
        print(message)                 # bytes of output; str for daemon notices
print(logs.exit_code)                  # 5

# The daemon buffers, so attaching later replays the same history in one go.
output = sandbox.attach_logs(session_id).read_all()   # LogOutput(data, notices, exit_code)
print(sandbox.list_exec_streams())     # [ExecStreamSession(id, command, args, started_at, exit_code), ...]
```

- **`sandbox.exec_stream(command, args=None, env=None)`** — starts `command` detached and returns a session id immediately. `env` is merged over the sandbox's own.
- **`sandbox.attach_logs(session_id)`** — returns a `LogStream`: the full captured history first, then new output, whether or not the process has finished. Messages are `bytes` of output, or `str` for the daemon's notices (truncation, and the final `[process exited with code N]`). `exit_code` is set once that notice is seen; `read_all()` drains the stream into a `LogOutput`. Same `recv(timeout)`, iteration and context-manager behaviour as `PtySession`.
- **`sandbox.list_exec_streams()`** — every session tracked against this sandbox, as `ExecStreamSession` (`exit_code` is `None` while running).
- Not carried across `resume()`/`fork()`, and gone after a daemon restart. `AsyncSandbox` has the same three methods, awaited, with `AsyncLogStream`.

### Copying directory trees

```python
result = sandbox.upload_dir("./project", "/work", exclude=lambda rel: rel.startswith(".git/"))
print(result)   # TransferResult(files=…, directories=…, symlinks=…, bytes=…, skipped=[…])
sandbox.run_command("sh", ["-c", "cd /work && make"])
sandbox.download_dir("/work/out", "./out")
```

- **`sandbox.upload_dir(local_dir, remote_dir, exclude=None, concurrency=8)`** and **`sandbox.download_dir(remote_dir, local_dir, exclude=None, concurrency=8)`** — copy a whole tree, keeping file modes and symlinks, `concurrency` files at a time. `exclude` receives each entry's `/`-separated path relative to the root and skips it when it returns true. Both return a `TransferResult` (`files`, `directories`, `symlinks`, `bytes`, `skipped`).
- The guest is untrusted, so `download_dir` validates what it lists: an entry name that is not a single plain path component (`..`, a separator, a NUL) raises `ValueError`; a symlink is only recreated when its target resolves inside `local_dir` (existing links on disk are followed in that check), and any other is listed in `skipped`; duplicate names in one listing are refused; files are created `0600` without following links, then given the listed permission bits with setuid/setgid/sticky dropped. A hostile guest cannot write outside `local_dir`.

### Snapshot, resume, fork

```python
snapshot_id = sandbox.snapshot()  # save state, stop the VM

# ...later, possibly in a different process...
resumed = Sandbox.resume(snapshot_id)  # consumes the snapshot
resumed.run_command("echo", ["back from a snapshot"])

# Or keep the snapshot reusable by forking instead of resuming:
fork1 = Sandbox.fork(snapshot_id)
fork1.stop()  # frees the fork; the snapshot is still there
fork2 = Sandbox.fork(snapshot_id)  # fork it again
```

- **`sandbox.snapshot()`** — saves full state to disk and stops; returns a snapshot id.
- **`Sandbox.resume(snapshot_id, base_url=None, auth_token=None)`** — boots from a snapshot, **consuming** it.
- **`Sandbox.fork(snapshot_id, base_url=None, auth_token=None)`** — boots from a snapshot **without** consuming it. Raises `SandkilnApiError` (`409`) while an earlier fork is still live.
- **`Sandbox.list_snapshots(source_sandbox_id=None, base_url=None, auth_token=None)`** — lists snapshots. `source_sandbox_id` narrows to the one taken from that original sandbox id.

### Remote storage mounts

```python
sandbox = Sandbox.create()
mount = sandbox.mount("build-cache", "https://s3.example.com", access_key="...", secret_key="...", mount_path="/mnt/cache")
# Ordinary read_file()/write_file() against mount_path now read/write through to the bucket.
sandbox.unmount(mount.id)
```

- **`sandbox.mount(bucket, endpoint, access_key, secret_key, mount_path, read_only=False)`** — mounts an S3-compatible bucket at `mount_path` via `rclone mount`. `endpoint` is the full URL of the S3-compatible service, never defaulted; `access_key`/`secret_key` are written into a `0600` rclone config file inside the guest, never passed as a command-line argument. Needs the optional FUSE-capable rootfs setup described in [Manual host setup](/self-hosting/manual-setup#remote-storage-mounts-optional); raises `SandkilnApiError` on a guest-side mount failure. Not carried across `resume()`/`fork()` — it's a live guest FUSE process, already captured by Firecracker's own snapshot.
- **`sandbox.list_mounts()`** — lists every remote-storage mount currently active in this sandbox.
- **`sandbox.unmount(mount_id)`** — tears down one mount. Best-effort on the guest side — a failed `umount` is a daemon-log warning, not a failed request.
